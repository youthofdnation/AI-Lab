# SALPION Mac AI worker through RIAN Commander V2

Source integration, 2026-11-26. Based on the Fleet pool in PR #8 and approved inventory in PR #11. **Not deployed.** The live Mac V2 connector still advertises only `diag.wait`; V1 remains read-only. No Fleet policy, agent allowlist, Tailscale setting, ACL, firewall or production process was changed.

## Ownership and data flow

- RIAN Commander V2 owns the device roster, current inventory, recommendation, exact-scope owner approval, durable start/stop/status jobs and audit. The broker sends only a fixed job kind with `{}` params. There is no raw command, path, model choice, frame, token or shell in an AI job request.
- The Mac V2 agent checks its own allowlist and local denylist. `salpion.worker.start` loads an owner-pinned Python/script/weight SHA-256, private bearer token file, and state/log paths from **Mac-local config**. It starts the existing SALPION Nano MPS worker on `127.0.0.1`; `status` checks process identity and `/v1/health`; `stop` sends SIGINT only to a process whose PID, start time, script and state path match the RIAN record. Start and stop are never standing-grantable.
- Fleet `inventory` already reports CPU, RAM pressure, GPUs, AI process names and runtimes. The status result adds the worker model/hash/readiness to `rian_v2_fleet_status`; it never returns the bearer token. Mac MPS GPU utilization/VRAM is unavailable from the current inventory and stays `null`, not invented.
- SALPION PR #52 supplies the data plane: the Mac worker speaks the A100 `salpion-remote-detect-v1` HTTP contract and the opt-in `MacDispatchRunner` adapts `MacDetectorClient.predict(rgb)` to `GpuDispatchRunner.infer(bgr)`. 1Q keeps its local runner loaded. The existing dispatch circuit sends the same frame locally on timeout, disconnection or identity mismatch and probes the Mac again after cooldown. The Commander queue does not transport frames or make per-frame decisions.
- Tailscale may carry the approved **data** connection only. Current Mac Serve HTTPS routes `/` and `/brain` are occupied and unchanged. A separate reviewed tailnet-only route to the worker's loopback port, restricted to the 1Q identity, and private token provisioning on both hosts are required before a host-to-host test. Never use Funnel/public serving. Public CCTV stays on its authorized 1Q host.

2. Keep the existing mandatory denylist and quarantine rules. ## Current evidence and limits

- The new fixed lifecycle module started, health-checked and stopped a real Nano MPS worker **locally on the Mac** in 6.2 seconds, with state and owner record removed after stop (`experiments/mac-studio-ai-20261125/commander-local-lifecycle.json` in SALPION PR #52). This invoked the source module directly, not the deployed V2 connector.
- Existing Fleet/approval and Mac installer tests pass with the new kinds. No 1Q application request, Commander approval execution, production deployment or tailnet AI-worker route has been demonstrated.
- The V2 result records a loopback port and model hash but no token. The 1Q integration session must obtain its token through existing approved secret management. If that path is absent, host integration remains BLOCKED.
